# Dust2 weather command prototype, CS2 1.41.8.8

## Native behavior and verified module

Client module SHA-256:
`D7DB25D48F1D10C5E0B0296E20ED803426EB9509DA41760DAEDA39DD35BA89B9`.
Source revision 11076591, version 1.41.8.8. Addresses below are RVAs, not
absolute process pointers. Existing HLAE creation and control-point wrappers
uniquely match this build: particle manager getter 0x9E36E0, creation wrapper
0x7C90F0, world-position control-point update 0xA11EA0. The native update's
fifth parameter is float, so this module uses a float-typed call.

Native manager destroy at 0x9D6210 is an unhooked helper, not a replacement
handler. Disassembly checks index -1, searches manager's count at +0x98 and
record array at +0xA0, compares record index +0x38, stops emission, releases
the particle system and removes its manager record. The complete new pattern
in MirvWeather.cpp has exactly one match. Calls use immediate/remove true.
Owned index plus record pointer are checked before destroying; manager changes,
level initialization, demo jumps and shutdown clear owned state. These fields
are build-dependent and must be rechecked after CS2 updates.

## Independent controller and external resources

`mirv_weather 1` enables requested effects only in a Dust2 demo; `0` restores
them. It does not require `mirv_pov 1`. Weather is off at startup. Each subeffect
is configured with `mirv_weather rain|ground|postprocess 0|1`, and also has an
immediate Release debug control in the shared registry:
`mirv_pov_debug_feature weather_rain|weather_ground|weather_postprocess 0|1`.
Debug controls default to enabled; the weather master request defaults off.
Changes apply at the next render frame. `mirv_weather status` reports resource,
native function, particle host, material and volume states; `reload` resets
state and re-reads the independently installed resource manifest.

Reference data: CS2 Insight Agent commit
`f05c698c755dc7806855bb13a5c823dbf6a21de6`, separately licensed under PolyForm
Noncommercial 1.0.0 with its required copyright notice. No application code
from that project is linked into the DLL. A separate HLAE resource pack contains
its custom rain particle, 385 outdoor emitter positions, and 18 wet ground
materials. New resource paths avoid replacing the game's original materials.
Do not distribute that data as part of the DLL's source license.

HLAE's existing resources/AfxHookSource2/cs2 search path loads the separate
pack without editing gameinfo, replacing a map VPK, or running a launcher.
Rain uses world-origin attachment 8 and control point 0. The source definition
contains radius 64, continuous rate 16 per host, falling velocity and its native
impact child. Renderer behavior remains to be checked in a running demo.

Wet ground only substitutes matching materials for Base/Aggregate scene
objects. A private scene-data copy and forced primitive flushes prevent a
temporary material from modifying the map record or remaining in a queued
batch. Disabling stops substitutions immediately on the next frame.

Postprocessing resolves C_PostProcessingVolume.m_hPostSettings from schema,
loads the installed Train postprocess resource and substitutes volume resource
handles. It retains original handles associated with entity serials, honors
new native values while active, and restores only fields still pointing at our
resource. This resource is supplied by the installed game, not copied into the
pack. Native resource caching lifetime and volume refresh behavior need in-game
verification. Missing schema or resources leaves the effect off with a warning.

Sky is deliberately owned by the existing `mirv_sky material` command; weather
does not replace or reset the user's sky choice. Native baked map lighting is
not regenerated by a postprocessing change. This prototype adds no lightning
or thunder.

## Validation and remaining uncertainty

Verified rain definition KV3, 385 positions, catalog hashes and 18 unique material
payloads. Verified native patterns against the current client and reviewed
state transitions for on/off, re-enable, debug controls, seek, level and shutdown.
Windows Release x64 compilation and game checks must be recorded separately.
Runtime acceptance must include cold-start resource loading, wet surfaces,
postprocess appearance, indoor rain exclusion, demo rewind/seek, off/on,
POV off/on, mirv_sky custom/default and scene-filter/recording interactions.
385 emitters plus per-draw flushes may affect performance. Compilation alone
does not confirm visible wetness, rain or volume refresh.
