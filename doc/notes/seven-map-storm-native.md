# Seven-map storm behavior and validation

The controller extends the existing Dust2, Mirage, Cache, Inferno, Ancient, Nuke and Anubis weather profiles. Existing rain, wet-ground and contact data are unchanged. It preserves the selected mirv_sky material and adds adjustable sunlight reduction, sun-card suppression, scene exposure, grading, rain audio and thunder. The lightning visuals are cancelled and absent from this build: there is no bolt or cloud particle, no flash or white-screen blend, no transient light/environment illumination, no owned transient lifetime/binding and no manual particle probe. Removal is unconditional in the code, not a disabled default. The weather resource package remains the original 47 files and contains no `storm_bolt.vpcf_c`.

## Thunder semantics

Kill-triggered thunder requires at least one mirv_deathmsg filter rule. With no filters, no kill schedules thunder, even if deathmsg debug, lifetime or highlighting is configured. With configured filters, only the final nonblocked real, non-self kill schedules it. The notification belongs exclusively to the right-top killfeed handler after the complete filter and block decision; the POV DeathPanel does not notify weather. The xTrace rule resolves its player when the rule is added. No camera re-trace is introduced.

Demo-time thunder is independent of the filter list. `mirv_weather lightning demo|kills|both|off` is retained only as an audio-only compatibility trigger: it selects which accepted events schedule the delayed thunder and never generates a lightning particle. Pausing, disabling, changing maps and seeking clear the delayed thunder and pending kill events. Multiple accepted kills in one render-frame batch share a single delayed thunder burst; the accepted-kill counter records each kill. The `paused` field in the status line is the demo pause state of the last weather frame, so a `rainAudio`/`thunderAudio` of 0 while paused is expected rather than a failure.

The demo interval schedules thunder on a demo-time cell change, the kept kill schedules it with the short post-kill delay, and the manual test schedules it with the demo-length delay. No event places particle control points, spawns a resource, computes a camera-relative strike, or changes the selected sky.

## Rendering and audio ownership

Grading uses a private deferred D3D11 context and executes with context-state restoration. It preserves predication, avoids duplicate processing of the same target in one presented frame, and excludes the entire POV death-fade window and active player flash. HUD is drawn later. BeforeUi stream capture and ReShade input include the grade, so additional ReShade grading can compound the appearance. Owned draws bypass HLAE's color/depth blockers and must be included in recording acceptance. The pass applies the permanent exposure/saturation/highlight/cool/shadow grade only; the former transient white-screen blend and its flash term are removed, while the smoothstep white protection that keeps a native full-white flash intact remains.

Multisampled scene colour is supported instead of being rejected. When the current target is MSAA (2x/4x/8x and the MSAA view dimension), the pass first resolves the multisampled target into an owned single-sample colour texture, samples that texture in the fullscreen pass, and still draws back into the original multisampled render target. The single-sample texture is created with the typed resource format (an RTV view format is always typed, so a typeless resource resolves through its view format), its shader-resource view is created with the typed view format, and the resolve only runs when the device reports multisample-resolve support for the format. Only a single-array-slice, single-mip, single-sample-resolution target is accepted; other view dimensions, formats, arrays, mips and sample counts are refused. The previous native depth/stencil state, blend state, viewport binding and predication are untouched: the copy/resolve happens on the immediate context with predication cleared for the resolve/copy/execute window and restored afterwards, and the owned record is executed with command-list state restoration. There is deliberately no after-HUD fallback, so a refused target loses grading rather than being drawn at the wrong point in the frame. A refusal is latched per target signature so the same unsupported target is diagnosed once instead of every presented frame; counters show whether the target was reached, which sample count and formats were seen, the last refusal reason and any resolve/draw error. These counters prove only that the pass was attempted, never that the result is visible.

Native scalar overrides are restored only for matching entity identities and values still owned by this controller. The permanent sun reduction is a brightness scale on `C_LightEnvironmentEntity`; no transient light boost remains. Audio playback tracks only its own instances and never issues global stopsound. Rain is a stereo ambient loop, without roof-aware indoor/outdoor routing. Turning both audio effects off stops the instances before releasing their definition references; reload or map reset allows a failed definition lookup to retry. Illumination and thunder switches remain independent.

Storm audio does not latch a failed native initialization for the rest of the process, and it no longer depends on the POV sound-circle. Weather resolves and validates its own owned sound interface through `MirvPovSoundCircle_InitializeOwnedAudio`: the unique direct start helper, the sound-event interface global reached from that helper's validated tail, the unique stop wrapper (with its validated callee prefix) and the owned system singleton. It installs no radar, local-pawn or network sound hook, and a failed POV initialization cannot clear or gate it. Initialization is only considered complete once the owned start helper, event interface, stop helper and system slot are all present; until then it is retried at a bounded, backing-off cadence (a few seconds, capped), so a transiently unavailable interface can still come up later without a per-frame cost. Readiness fails closed when any native pattern or instruction tail no longer matches. Status reports structured owned readiness (owned/start/stop/system/event-interface), the number of initialization attempts, the most recent owned-sound failure stage (init, start, stop, system, event-interface, name validity or GUID), and per-rain/per-thunder attempt and success counts. The registered-event stages are computed independently of whether a playback GUID is currently active or the demo is paused, and they are reported separately from retained sound definitions. No native function address, pattern or ABI was changed for this.

Rain spawn diagnostics report the attempt count, definition-load failures, create failures, created count, live count and a short failure stage, plus the early-return reason for the spawn as a whole (layout/native-interface/resource-system/manager/definition/create/record). These are submission counters and do not prove visible output; they exist so a missing definition can be told apart from a missing manager or a rejected create. They are printed only by the status command, never per frame, and never print addresses. No lightning counter or bolt/cloud line exists.

The storm effects each have an immediate Release mirv_pov_debug_feature control (`weather_sun`, `weather_exposure`, `weather_grade`, `weather_rainsound`, `weather_thunder`). The removed `weather_lightning` and `weather_lightning_light` entries no longer exist in the registry. Weather does not require mirv_pov. Weather resolves its own owned sound interface and never installs the POV soundcircle hooks, so the independently gated POV behavior is unaffected. The guide lists commands and defaults.

The default rain volume is 1.0 (previously 0.45) and the default thunder volume is 0.55; both remain adjustable in 0..1 through `mirv_weather rainsound` and `mirv_weather thunder`.

## Manual compatibility test

`mirv_weather lightning test` is an audio-only compatibility request. It is queued and consumed on the next normal weather frame that is active and unpaused; while paused it stays queued, and a seek, map change, storm reset or disabling the storm layer drops it. It schedules one delayed thunder independently of the demo-time schedule and of the kill-filter mode, and it has its own counter, so it can never be mistaken for an automatic demo event or a retained kill. It does not fabricate a kill event, does not spawn any particle, and does not change the selected sky. It follows `weather_thunder`; if that switch is off the queued request is reported as ignored. A manual test that fires does not imply that automatic kill triggers were exercised.

## Validation boundary

Independent review identified rendering-state and cleanup defects; the fix round isolates drawing and preserves the fade transition. The user's explicit cancellation of all lightning visuals is authoritative; the final change removes bolt/cloud generation, transient lifetime and bindings, the manual particle probe path, the white-screen blend, the flash-driven light boost and the two visual feature entries, while keeping permanent sun/exposure/grade, MSAA before-HUD rendering, the full-white native flash, the demo/kill thunder schedule and the owned rain/thunder audio. Local static review and whitespace checks are followed by cloud Windows Release x64 and exact embedded HLSL VS/PS compilation. Downloaded DLL/source correspondence and installed-file checks are required before delivery.

Compilation, review and counters do not establish visible or audible success. In-game seven-map indoor/outdoor lighting, actual rain/thunder audio, filtered-kill behavior, repeated seeks, pause/restore, full-white flash, death fades, HUD and recording remain acceptance items. Existing baked lightmaps/reflections are not rebuilt. Detailed native investigation records remain local rather than being included in the public diagnostic corpus, and the final resource package is the original 47 weather resources with no authored bolt.
